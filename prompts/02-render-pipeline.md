# 02 — Render pipeline hardening

## Context (shared by every prompt)
You are working on **Komorebi-chō**, a free, web-first, cozy living-diorama game: a fictional Yanaka-style Tokyo shitamachi block on a walnut plinth. It's rendered in three.js (`WebGLRenderer`, r187+) at low resolution through a palette + Bayer-dither post pass, so it reads as pixel art. Residents follow schedules and a utility AI, notice what the player places, and adapt their routines. **All art and audio are generated by code.** No purchased or commissioned assets, no image or audio files.

Read `CLAUDE.md` and `docs/ARCHITECTURE.md` before touching code. Respect the non-negotiables there:
- code-only art
- the palette is law
- no fail states
- never teleport visible residents
- edits are transactions
- determinism via named RNG streams
- respectful, fictional specificity
- a 60 fps budget

Working method:
- Plan first. List the files you will touch and why.
- Implement in small steps. After each one, run `npm run typecheck` and `npm test`.
- Run the dev server and **look**: capture screenshots (Playwright or the browser) at hours 6, 12, 18 and 22, plus rain. Compare them to the screenshots from before your change.
- New logic in `src/sim`, `src/core` or `src/audio/theory.ts` needs unit tests.
- Don't add a dependency unless it removes more complexity than it adds. Say why.
- Finish with a short report:
  - what changed
  - screenshots
  - known gaps
  - which acceptance criteria you verified, and how

## Goal
Make the pixel pass robust, fast and measurable without changing its character.

## Tasks
1. **Palette LUT.** Replace the per-pixel loop over `pal[]` in `src/render/post.ts` with a 3D LUT. Bake a 32³ (or 64³) `Data3DTexture` once at startup that maps sRGB → nearest palette colour, using the same weighted distance. Sample it with nearest filtering after dithering. Keep the loop path behind a `?lutOff` flag so you can compare.
2. **Colour audit.** Write `docs/COLOR.md`, which explains:
   - the colour space at each stage (linear in the RT, sRGB after `toSRGB`, palette in raw sRGB)
   - why `THREE.Color` is not used for palette uniforms
   - that every `CanvasTexture` used as albedo has `colorSpace = SRGBColorSpace`

   Fix anything that violates this.
3. **Stability.**
   - Keep texel snapping.
   - Make rotation step-wise with a short crossfade: render the old and new views into two RTs for 250 ms and dissolve with the Bayer pattern. Crawling during rotation should be invisible.
   - Make zoom snap to integer pixel scales so pixels never become non-square or uneven.
4. **Pixel scale presets.** "Fine", "Classic" and "Chunky", each chosen so the render height lands in 220–300 px regardless of screen size. Make DPR handling explicit.
5. **Context loss.** Handle `webglcontextlost`/`restored`: pause, rebuild the render targets and post material, then resume. Test it with `WEBGL_lose_context`.
6. **Shadows.** Shadow camera bounds tight to the plinth. Bias tuned per time of day, with no acne at noon and no peter-panning at dusk. Shadow softness comes from the pixel pass, not PCF radius.
7. **Glow.** Move the 24-tap glow gather into a separate low-res bright pass at half the RT resolution, then composite. Clamp so a cluster of 20 lanterns never blows out: test by placing 20 stone lanterns in one spot.
8. **Seeded screenshots.** Add `?seed=N&hour=H&season=S&weather=clear|rain&freeze=1`. It freezes time and residents at a deterministic state, for screenshot tests.

## Acceptance criteria
- Visual diff of the LUT path against the loop path is under 0.5% of pixels at 5 reference shots.
- Frame time on the reference laptop drops or stays the same (report the numbers).
- 20 clustered lanterns at night show no blown-out white patch, and exposure stays within ±1 EV of the authored value.
- Rotation shows no visible crawl, and the context-loss test recovers within 1 s.

## Verify
- Playwright script capturing the reference shots via the seed URL.
- Before/after timings from `?debug`.
