# 12 — Performance & desktop-companion mode

## Context (shared by every prompt)
You are working on **Komorebi-chō**, a free, web-first, cozy living-diorama game: a fictional Yanaka-style Tokyo shitamachi block on a walnut plinth. It's rendered in three.js (`WebGLRenderer`, r187+) at low resolution through a palette + Bayer-dither post pass, so it reads as pixel art. Residents follow schedules and a utility AI, notice what the player places, and adapt their routines. **All art and audio are generated by code.** No purchased or commissioned assets, no image or audio files.

Read `CLAUDE.md` and `docs/ARCHITECTURE.md` before touching code. Respect the non-negotiables there:
- code-only art
- the palette is law
- no fail states
- never teleport visible residents
- edits are transactions
- determinism via named RNG streams
- respectful, fictional specificity
- a 60 fps budget

Working method:
- Plan first. List the files you will touch and why.
- Implement in small steps. After each one, run `npm run typecheck` and `npm test`.
- Run the dev server and **look**: capture screenshots (Playwright or the browser) at hours 6, 12, 18 and 22, plus rain. Compare them to the screenshots from before your change.
- New logic in `src/sim`, `src/core` or `src/audio/theory.ts` needs unit tests.
- Don't add a dependency unless it removes more complexity than it adds. Say why.
- Finish with a short report:
  - what changed
  - screenshots
  - known gaps
  - which acceptance criteria you verified, and how

---

## Goal
60 fps on modest hardware, near-zero cost when idle, and a "lives on your desktop" mode like Quack and Rusty's Retirement.

## Tasks
1. **Static batching.** Merge every static building and prop mesh by material (`BufferGeometryUtils.mergeGeometries`), or use `BatchedMesh`, after world build and after each edit (only the affected parcels). Use `InstancedMesh` for repeated props (grates, rim stones, fence posts, crops, blobs). Target under 250 draw calls.
   - Baseline after prompt 01, from `?debug` at the default view: about 1750 calls per frame. That is about 920 in the main pass plus about 830 in the shadow pass, from 902 meshes with 902 unique geometries over 181 materials. The overlay counts every pass in the frame, so shadow casters count twice.
   - Prompt 01's "under 600" criterion was deferred to here: merging static geometry before prompts 05 and 06 would fight the building grammar and moving buildings.
   - After prompt 03 (art direction): about 1870 calls at dusk and about 43k triangles; the frame takes about 1.9 ms longer on an M-series Mac, uncapped. The quiet props are already baked per material with `Kit.merged`, which is a model for the wider pass. The remaining new cost comes from the signs (one material and texture each; an atlas would batch them), weathered walls (subdivided about 1 m), the swaying-leaf shader and the pond reflection march in the composite.
2. **Shadow caching.**
   - Set `renderer.shadowMap.autoUpdate = false`.
   - Re-render shadows only when the sun moves more than 0.5°, when an edit lands, or for dynamic objects. Draw residents' shadows as blob decals (pixel-art style).
3. **Idle rendering.** If the camera, time scale and sim visuals haven't changed meaningfully, drop to 10–15 fps. When the tab is hidden, run the sim headless at 2 Hz with no rendering. Add a battery saver option (30 fps).
4. **Memory.** Dispose cloned textures and materials on removal (fix any leaks). Track `renderer.info.memory` across 200 edits; it should be flat.
5. **Companion mode** (web): a compact layout option, a slim strip view (camera auto-frames a slice of the street), no HUD, gentle sound. Make it the default for the desktop wrapper in prompt 14.
6. **Budgets file.** Write `docs/PERF.md` with targets and a method (which devices, which scene, how to measure), and a CI perf smoke test using headless Chrome with SwiftShader frame-time sampling, used as a regression signal.

## Acceptance criteria
- Under 250 draw calls and under 8 ms GPU on the reference laptop at the default view, at night with rain.
- Idle at noon: under 3% CPU in Chrome's task manager.
- Memory flat across 200 edits.
