# 01 — Foundation & CI

## Context (shared by every prompt)
You are working on **Komorebi-chō**, a free, web-first, cozy living-diorama game: a fictional Yanaka-style Tokyo shitamachi block on a walnut plinth. It's rendered in three.js (`WebGLRenderer`, r187+) at low resolution through a palette + Bayer-dither post pass, so it reads as pixel art. Residents follow schedules and a utility AI, notice what the player places, and adapt their routines. **All art and audio are generated by code.** No purchased or commissioned assets, no image or audio files.

Read `CLAUDE.md` and `docs/ARCHITECTURE.md` before touching code. Respect the non-negotiables there:
- code-only art
- the palette is law
- no fail states
- never teleport visible residents
- edits are transactions
- determinism via named RNG streams
- respectful, fictional specificity
- a 60 fps budget

Working method:
- Plan first. List the files you will touch and why.
- Implement in small steps. After each one, run `npm run typecheck` and `npm test`.
- Run the dev server and **look**: capture screenshots (Playwright or the browser) at hours 6, 12, 18 and 22, plus rain. Compare them to the screenshots from before your change.
- New logic in `src/sim`, `src/core` or `src/audio/theory.ts` needs unit tests.
- Don't add a dependency unless it removes more complexity than it adds. Say why.
- Finish with a short report:
  - what changed
  - screenshots
  - known gaps
  - which acceptance criteria you verified, and how

## Goal
Turn the scaffold into a healthy repo: real dependencies, a clean typecheck against the **real** `@types/three`, CI, and automatic deploys to GitHub Pages.

## Why
The scaffold was written and tested without network access. Its typecheck used a stub for `three`, so three.js API mistakes may be hiding. Find and fix them first.

## Tasks
1. Run `npm install`. Pin exact versions in `package.json` for `three`, `@types/three`, `vite`, `vitest` and `typescript`. Check each on npm today and record the versions in `docs/VERSIONS.md`.
2. Run `npm run typecheck` and fix every error properly. No `any`, no `@ts-ignore`. Expect issues around `Object3D.traverse` generics, `DepthTexture`, `PointsMaterial` and `Float32Array` typings.
3. Run `npm test` (vitest). All existing suites must pass unchanged.
4. Add ESLint (typescript-eslint, flat config) and Prettier, using the current code style (2 spaces, single quotes, 160 cols). Add `npm run lint`.
5. Add a `?debug` URL flag showing an overlay with:
   - FPS and frame time
   - draw calls, triangles and textures from `renderer.info`
   - sim tick time
   - the resident count shown on screen
6. GitHub Actions:
   - `ci.yml` runs install, lint, typecheck, test and build on every PR.
   - `pages.yml` deploys `dist/` to GitHub Pages on `main`. `base: './'` is already set.
7. Add `docs/CONTRIBUTING.md` covering branch naming (`pNN-topic`), the PR template with screenshots, and the definition of done.
8. Confirm the game runs from `npm run dev` and from the built `dist/` via `npm run preview`. Fix any console errors or warnings.

## Acceptance criteria
- `npm run lint && npm run typecheck && npm test && npm run build` passes locally and in CI.
- The deployed Pages URL loads with zero console errors at Dawn, Noon, Dusk, Night and in Rain.
- `?debug` shows live stats, and draw calls are under 600 at the default view.

## Verify
- Run the commands above.
- Open the Pages URL in Chrome and Firefox and take screenshots at each time of day.
- Paste the `renderer.info` numbers into the PR.

## Out of scope
Visual changes. Don't "improve" the look in this PR.
